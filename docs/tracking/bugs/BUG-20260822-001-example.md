# BUG Example: Shortcuts Execution Timeout

**ID**: BUG-20260822-001-shortcuts-timeout-example  
**Status**: open  
**Priority**: P1-high  
**Created**: 2026-08-22  
**Updated**: 2026-08-22  
**Assignee**: ai  

## Description

Shortcuts execution times out after exactly 5 seconds, even when the shortcut requires more time to complete.

## Context

Discovered while implementing GSD Task 2.3.2 (Implement timeout mechanism for Shortcuts).

The timeout is too aggressive for complex shortcuts that perform multiple operations (e.g., file processing, API calls).

## Reproduction Steps

1. Create a shortcut that waits 10 seconds
2. Execute via `local_automation_execute`
3. Observe timeout error after 5 seconds

## Expected Behavior

- Default timeout: 30 seconds
- Configurable timeout via request parameter
- Clear timeout error message
- Proper cleanup of timed-out process

## Actual Behavior

- Hard-coded 5 second timeout
- Process may not be properly terminated
- Error message unclear

## Impact

- Users cannot run legitimate long-running shortcuts
- False negatives in Phase 2 testing
- Blocks GSD tasks 2.3.3 and 2.3.4

## Linked Items

- GSD Task: 2.3.2 (where discovered)
- Blocking Tasks: 2.3.3, 2.3.4
- Related Issues: None

## Acceptance Criteria

- [x] Timeout is configurable (default 30s)
- [ ] Timeout parameter validated (1-300 seconds)
- [ ] Process properly terminated on timeout
- [ ] Clear error message with elapsed time
- [ ] Test coverage for timeout scenarios

## Investigation Notes

```swift
// Current code (ShortcutsProvider.swift:45)
let timeout: TimeInterval = 5.0  // ← HARDCODED!

// Should be:
let timeout = request.timeout ?? 30.0
guard timeout > 0 && timeout <= 300 else {
    throw CapabilityError.invalidParameter("timeout", "1-300 seconds")
}
```

## Proposed Fix

1. Add `timeout` parameter to AutomationRequest
2. Validate range (1-300 seconds)
3. Pass to process execution
4. Update tests to verify configurable timeout
5. Document in API reference
